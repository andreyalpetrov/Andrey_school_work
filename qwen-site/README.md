# Сайт для локальной нейросети qwen3:4b

Flask-сайт с регистрацией, входом и чатом. Пользователи хранятся во внешней базе MySQL, нейросеть работает через Ollama на этом же сервере.

## Что в архиве

```
qwen-site/
├── app.py                     сервер на Flask: регистрация, вход, чат
├── pyproject.toml             список библиотек для uv
├── uv.lock                    точные версии библиотек (создан uv, руками не править)
├── requirements.txt           тот же список для запуска без uv
├── .env.example               образец файла настроек (база, ключ, адрес Ollama)
├── templates/
│   ├── base.html              общий каркас страниц
│   ├── login.html             страница входа
│   ├── registration.html      страница регистрации
│   └── chat.html              страница чата
├── static/
│   ├── style.css              оформление
│   ├── auth.js                логика форм входа и регистрации
│   └── chat.js                логика чата и стриминга
└── deploy/
    ├── qwen-site.service      служба systemd (автозапуск сайта)
    └── ai.androprojects.ru.conf   настройка nginx
```

Адреса страниц: `/` — чат (только после входа), `/login` — вход, `/register` — регистрация.

## Запуск на сервере (Debian 12)

Все команды выполняются на сервере от имени root. Если вы работаете под обычным пользователем, добавляйте `sudo` в начало.

### Шаг 1. Установить программы

```bash
apt update
apt install -y nginx unzip curl
```

Затем установите uv — программу, которая сама создаёт окружение Python и ставит все библиотеки проекта:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source $HOME/.local/bin/env
uv --version
```

Последняя команда должна показать номер версии. Если `uv` не находится, закройте терминал и подключитесь к серверу заново.

### Шаг 2. Скопировать проект на сервер

На своём компьютере (замените `IP_СЕРВЕРА` на адрес сервера):

```bash
scp qwen-site.zip root@IP_СЕРВЕРА:/tmp/
```

На сервере:

```bash
unzip /tmp/qwen-site.zip -d /opt/
cd /opt/qwen-site
```

Проект окажется в папке `/opt/qwen-site`. Остальные шаги рассчитаны на этот путь.

### Шаг 3. Установить библиотеки Python

```bash
cd /opt/qwen-site
uv sync --python /usr/bin/python3
```

Эта одна команда создаёт папку `.venv` и ставит в неё все библиотеки в версиях, записанных в `uv.lock`. Параметр `--python /usr/bin/python3` заставляет uv взять системный Python 3.11: служба сайта работает от пользователя `www-data`, и Python из домашней папки root ей был бы недоступен.

Запасной вариант без uv:

```bash
apt install -y python3-venv
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### Шаг 4. Создать файл настроек

```bash
cd /opt/qwen-site
cp .env.example .env
sed -i "s/^SECRET_KEY=.*/SECRET_KEY=$(python3 -c 'import secrets; print(secrets.token_hex(32))')/" .env
```

Вторая команда записывает в `.env` случайный секретный ключ. Данные базы в `.env.example` уже заполнены значениями из вашего исходного `app.py`. Если пароль базы поменяется, исправьте строку `DB_PASSWORD` в `.env`.

Закройте файл от посторонних:

```bash
chown -R root:www-data /opt/qwen-site
chmod 640 /opt/qwen-site/.env
```

### Шаг 5. Проверить Ollama

```bash
curl http://127.0.0.1:11434/api/tags
```

В ответе должна быть модель `qwen3:4b`. Если команда не отвечает, запустите Ollama: `systemctl start ollama`.

### Шаг 6. Пробный запуск

```bash
cd /opt/qwen-site
uv run app.py
```

(Без uv: `.venv/bin/python app.py`.)

Откройте второе окно терминала на сервере и выполните:

```bash
curl -I http://127.0.0.1:8000/login
```

Должна прийти строка `HTTP/1.1 200 OK`. После проверки остановите пробный запуск клавишами Ctrl + C.

### Шаг 7. Автозапуск через systemd

```bash
cp /opt/qwen-site/deploy/qwen-site.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now qwen-site
systemctl status qwen-site
```

В выводе последней команды должно быть `active (running)`. Сайт теперь запускается сам после перезагрузки сервера.

### Шаг 8. Настроить nginx и домен

1. В панели управления доменом `androprojects.ru` создайте A-запись `ai`, указывающую на IP сервера (если её ещё нет).
2. Подключите настройку сайта:

```bash
cp /opt/qwen-site/deploy/ai.androprojects.ru.conf /etc/nginx/sites-available/
ln -s /etc/nginx/sites-available/ai.androprojects.ru.conf /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx
```

Команда `nginx -t` должна ответить `test is successful`.

3. Если на сервере включён файрвол ufw, откройте порт 80: `ufw allow 80/tcp`.

### Шаг 9. Проверить сайт

Откройте в браузере `http://ai.androprojects.ru`. Появится страница входа. Зарегистрируйтесь, после этого откроется чат.

## Как это работает

- **Пароли.** Хешируются функцией `hashlib.pbkdf2_hmac` (SHA-256, 600 000 повторов, случайная соль для каждого пользователя). В столбец `password_hash` пишется строка около 90 символов вида `pbkdf2_sha256$600000$соль$хеш`.
- **База.** Сайт выполняет только запросы к таблице `users` по столбцам `username`, `email`, `password_hash`: поиск пользователя и добавление, как в вашем примере. Структуру таблицы он не меняет.
- **Чат.** История хранится только в браузере и пропадает при перезагрузке страницы. Кнопка «Новый диалог» очищает её без перезагрузки. Модели отправляются последние 30 сообщений.
- **Одна генерация за раз.** Пока модель отвечает одному человеку, второй получит сообщение «Модель сейчас отвечает на другой запрос». Кнопка «Стоп» прерывает генерацию и на стороне Ollama.
- **Вход.** После 10 неудачных попыток с одного IP вход блокируется на 10 минут.

## Что важно знать

1. **Старые аккаунты не будут работать.** Исходный `app.py` записывал пароли открытым текстом. Такие записи не проходят проверку хеша, и войти под ними нельзя. Эти пользователи должны зарегистрироваться заново с другим именем и почтой, либо старые строки нужно удалить из базы.
2. **Длина столбца `password_hash` неизвестна.** Нужно не меньше 90 символов. Если столбец короче, регистрация покажет ошибку про столбец `password_hash`. Если база молча обрезала хеш, сайт сам удалит эту только что добавленную запись. В этом случае столбец должен расширить тот, у кого есть доступ к базе.
3. **Сайт работает без HTTPS.** Пароли и переписка идут по сети в открытом виде. Когда будете готовы, HTTPS включается двумя командами:

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d ai.androprojects.ru
```

4. **Порт 11434 (Ollama) не открывайте в интернет.** Сайт обращается к Ollama внутри сервера.
5. **Сервер должен иметь выход к базе** `185.114.247.43:3306`. Проверка: `nc -vz 185.114.247.43 3306`.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| Сайт не открывается по домену | Проверьте A-запись (`ping ai.androprojects.ru`), `systemctl status nginx`, открыт ли порт 80 |
| Ошибка 502 Bad Gateway | Сайт не запущен: `systemctl status qwen-site`, затем `journalctl -u qwen-site -n 50` |
| В журнале «не задан SECRET_KEY» | Повторите шаг 4 |
| Служба не стартует, в журнале `No such file or directory` про `.venv/bin/gunicorn` | Не выполнен шаг 3: `cd /opt/qwen-site && uv sync --python /usr/bin/python3` |
| «База данных недоступна» | Проверьте данные в `.env` и доступ к базе (пункт 5 выше); подробности в `journalctl -u qwen-site -n 50` |
| «Не удалось подключиться к Ollama» | `systemctl start ollama`, затем проверка из шага 5 |
| «Ollama вернула ошибку 404» | Модель называется иначе: посмотрите `ollama list` и исправьте `OLLAMA_MODEL` в `.env` |
| Ответ приходит целиком, а не по частям | Проверьте, что в настройке nginx есть строка `proxy_buffering off;` |

После любого изменения файлов или `.env` перезапустите сайт:

```bash
systemctl restart qwen-site
```

Журнал сайта в реальном времени: `journalctl -u qwen-site -f`.

## Как добавить или обновить библиотеку

```bash
cd /opt/qwen-site
uv add название-библиотеки      # добавить новую
uv lock --upgrade && uv sync     # обновить все до свежих версий
systemctl restart qwen-site
```
